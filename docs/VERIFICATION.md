# 2026-10-24：Codex 个人提醒流程实测

## 结论与环境

在一台 Windows 的 Codex 桌面环境中，使用 Python 3.12.14、已连接 Gmail 和 QQ 收件邮箱，完成一次新用户配置流程与一次真实定时唤醒后的再次检查。

验证对象是仓库 `main` 的 [75d46f0](https://github.com/lovely-car/tibo-reset-mailer/commit/75d46f01eb0c9c2a79343026203a13d88a18de60)，软件版本为 `v0.2.0-beta.1`。验证通过的是 **Codex 判断 + 已连接邮箱 + 宿主调度** 路线，未使用独立 SMTP 或额外模型 API。

所有记录使用独立验证目录，原有个人提醒继续每小时运行。本文仅公开脱敏结果；不附收件地址、邮件服务端 ID、个人路径、数据库或原始投递日志。

## 实际执行结果

| 环节 | 真实执行与结果 |
|---|---|
| 获取项目 | 从公开 GitHub 仓库全新 clone，确认提交版本 |
| 安装 | 新建独立虚拟环境，按声明依赖安装成功 |
| 初始化 | 使用独立的私有目录配置个人收件人，保留原提醒状态 |
| 读取来源 | `agent scan` 实际读取 X，得到 7 条可核验的本人帖子及回复；warnings 为空 |
| 判断公告 | 识别 1 组历史重置预告；没有把已过截止时间认定为重置已完成，其他无关或归属不足的帖子不作为新提醒 |
| 格式与时间 | 保留北京时间、洛杉矶时间、原文、原帖链接、`before` 截止语义及 PST/PDT 歧义 |
| 真实发信 | 经项目 `prepare → begin` 后调用已连接 Gmail；明确返回成功邮件 ID，再用 `confirm` 保存回执并初始化 |
| 最终收件 | 收件人在聊天中明确确认“已收到，内容正常”，核实 QQ 实际收件 |
| 自动唤醒 | 宿主临时定时任务实际触发，再次执行项目 `agent scan`，没有由当前安装步骤手动冒充触发 |
| 去重 | 再次检查返回 `action: quiet`、`new_versions: []`、`warnings: []`；投递数和发送尝试次数均保持为 1 |
| 清理 | 实际删除临时验证任务；原有每小时提醒保持启用 |

初次实时扫描发生于 2026-10-24 09:52 UTC；自动唤醒后的再次读取发生于 10:02 UTC。为缩短验证等待，临时任务采用每分钟间隔并在一次检查后删除；这不是连续多小时的运行测试。项目个人配置中的默认间隔仍为每小时。

验证期间，沙箱曾拒绝访问由提升权限命令创建的私有文件。Codex 在用户授权范围内，经宿主权限机制继续读取同一状态完成验证，没有重建数据库或绕过去重。其他环境的运行权限应在安装时单独核实。
