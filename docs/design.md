v0.2.1 增加独立于 seen 的 reviews/review_audit 和已核验 observations：本轮实时取得的候选才能触发提醒，历史记录只提供上下文；未确认候选保留并重新读取官方线程。引用卡片不能覆盖原帖自己的 ID/时间，也不能覆盖之前独立核验的同帖边。系列简写需要近期已核验的 Codex 重置锚点，并标明推断依据。事件按具体时间/完成确认去重，不以无关新回复改变身份。SQLite 通过新增表升级，原初始化、已读、待发邮件和回执保留。

v0.2 新增 Codex 辅助路线：`agent scan` 提供公开证据，Codex 判断后 `prepare` 校验引文并预留邮件，`begin` 记录发送尝试，再通过宿主邮箱发送，`confirm --receipt-id` 原子保存真实服务端邮件 ID 和首次初始化。无 SMTP / 模型 API 配置；宿主的邮箱和定时能力需部署时核验。配置、扫描和去重使用独立的私有 agent 数据目录，不能直接复用其他监测器状态。操作步骤见 [CODEX_SETUP.md](../CODEX_SETUP.md)。下面保留独立运行路线的设计。

## 产品范围

目标用户是希望收到中文、双时区公告邮件的 Codex 用户。用户自行配置 SMTP 并部署。成功标准是配置后能收到测试邮件，在同一持久状态下重复运行不重复提醒，来源失败不产生假的“无公告”结果。

第一版只有一个来源账号、一位收件人、邮件一种投递方式。不包含账号额度查询、网页订阅后台、付费服务、多账号抓取、完整历史统计或实时通知承诺。

## 数据流程

`X 本人公开页面 → 作者/时间/链接核验 → 相关原帖补全 → 规则或模型判断 → 时区转换 → SQLite 待发记录 → TLS SMTP`

- `source.py` 只读取固定的官方 X 主机与本人帖子路径，限制响应大小并核验作者、正文、明确时间戳。不通过推文 ID 猜时间。
- `analysis.py` 将同帖主帖与本人上下文合并。默认保守规则；可选模型 JSON 结果还要核验原始引用、帖子 ID、时间或完成证据。模型不拥有发信或状态修改工具。
- `timing.py` 使用 IANA 时区；相对时间绑定原帖，固定缩写与洛杉矶当地时区的差异显式呈现。
- `state.py` 使用 SQLite 事务、帖子 ID + 完整正文 SHA-256、操作系统进程锁。无需原始 Skill 的状态工具。
- `review.py` 保留来源证据、待复查状态、上下文指纹和判断原因；`agent complete` 不再把所有不匹配候选直接标读。
- `service.py` 先保留待发记录与帖子版本，再投递。已知失败优先重试，歧义状态暂停自动重试。初始化只有在汇总 SMTP 接受后完成。
- `mail.py` 生成纯文本与转义后的 HTML 邮件，强制 TLS 或 STARTTLS；发送前生成稳定 Message-ID。连接在 DATA 接受后关闭失败不会把成功状态误改为失败。

## 已知边界

公共 HTML 访问与页面结构会变化，目前只声称可见范围，不声称完整时间线。当前解析器在作者同一原帖页面找到的补充标为上下文，不把它当作经 API 核验的直接回复边。判断时还需要上下文明显对应 Codex 重置。

规则模式会牺牲召回率来降低误报，模型模式也不能保证零错误。原始日期缺失时不换算；具名星期或周期原文可以通知，但第一版不会猜出下一个具体日期。暂不解析自然语言月份日期等所有时间表达。

重置“预告”与“已完成确认”是不同状态。首次完成事件计数只接受明确完成文字，不因预告截止时间过去而推断已完成。同一帖组合合并为一个事件；不同未明确关联主帖不强行合并，避免把不同额度窗口混为一谈。

SMTP 不支持跨本地数据库和远端邮箱的原子事务，因此不能保证数学意义的 exactly-once。对未知结果停下并允许人工核对，是第一版减少重复通知的选择。SQLite 包含收件人、邮件正文和状态，必须放在私有持久目录；公共临时 CI 运行器仅用于测试和无邮件的来源检查。

## 发布验证

单元与集成测试使用合成 HTML、固定时间、临时 SQLite、可控 SMTP/模型替身。公开源码中只保留脱敏演示，不复制个人运行数据库或凭据。

真实 X 来源可以用 `check --dry-run` 验证。真实 SMTP、特定模型兼容性及 Docker 运行以使用环境中的结果为准，不能把替身测试说成真实邮件已投递。
