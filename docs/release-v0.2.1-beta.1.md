# Tibo Codex 额度重置监测与邮件提醒 · v0.2.1-beta.1

这次修复“已经抓到疑似重置公告，却因短帖没重复写 Codex 而被标成已读”的漏提醒路径。

## 更新

- 结合同帖本人回复、本人引用关系与已核验的近期系列锚点判断简短公告，并标明上下文判断依据。
- 证据不足的候选保留待复查；正文不变但本人补充变化时重新判断，旧已读标记不再永久吞掉待复查候选。
- 引用帖正文绑定本帖自己的 ID 和时间；被引用内容单独记录，其他作者内容不当作 Tibo 本人说法。
- 支持 `By midnight PST/PDT/PT`，保留截止含义、发帖日期锚定及 PST/PDT 歧义。
- 同一具体计划/完成确认不因无关新回复重复发信；同时修复独立 SMTP 路线“warnings + 空证据”错误初始化的问题。
- 判断理由、版本和上下文指纹保存在各使用者的私有 SQLite，发送仍需真实邮箱回执；未知结果先核对已发送。

## 升级

让自己的 Codex 按 [CODEX_SETUP.md](../CODEX_SETUP.md#已部署用户升级) 更新原部署，保留原私有目录和每小时任务，重新安装后执行一次新的 `agent scan`。原 SQLite 自动增加所需表；不要清空去重记录，不要另建第二套提醒。独立 JSON 监测器不会自动迁移成这个项目的 SQLite。

## 验证和边界

本地 Windows / Python 3.12 的 67 项离线测试通过，覆盖短帖、引用帖、待复查、时区、重复投递和 SQLite 升级回归。新版运行时实际读取官方 X 成功：6 条可核验证据、无 warnings，识别出本人完成确认，生成并预留对应邮件；再次扫描先恢复 pending。这次发布验证没有发送额外测试邮件，没有创建新的定时任务。

历史真实收件验证的范围见 [实测记录](VERIFICATION.md)，不能把离线测试、生成内容或预留状态当作本版本在所有环境的真实投递证明。

继续标为 **Beta**。X 匿名公开页可能读取失败或只提供部分历史；设备离线、邮箱连接和宿主定时器仍会影响提醒。项目只监测公开公告，不读取个人账户额度。未知语义保留待核验，不保证所有简写都能自动确定。

仓库和安装包不包含任何人的邮箱、令牌、数据库、运行日志或邮件回执。
