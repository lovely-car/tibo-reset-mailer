# 故障排查

## 先确认正在使用哪条路线

- **由 Codex 配置的个人提醒**：请让同一个 Codex 读取 [CODEX_SETUP.md](../CODEX_SETUP.md) 和 [每轮执行说明](CODEX_MONITOR.md)，使用部署时保存的 Python 与私有数据目录。检查命令是 `agent scan` / `agent status`，发信通过已连接邮箱完成。
- **自己配置的 Python + SMTP**：使用[高级手动部署](ADVANCED_SETUP.md)中的 `doctor`、`check`、`status` 和 `resolve`。该路线有单独的配置、状态目录和已知问题。

两条路线的命令和数据目录不能混用。不要为了排查重新初始化、删除数据库或新建第二套重复提醒。

## Codex 已经安装，但没有收到邮件

可以把下面这段话发回原来的 Codex：

```text
请检查你为我配置的 Tibo 个人提醒：使用已有私有数据目录和解释器，读取 agent status，核对最近一次实际 X 抓取、邮箱连接和每小时任务状态。
若有 pending/unknown 投递，按 docs/CODEX_MONITOR.md 先核对已发送记录并处理，避免重复发信。
请分别说明来源是否可读、是否有符合条件的新公告、邮箱服务是否返回成功回执，以及定时任务是否确实存在。不要重新安装或重置去重状态。
```

邮箱服务返回成功回执后，仍需使用者检查收件箱及垃圾邮件。没有新的明确公告时，正常行为是保持安静。首次有效扫描会发送一次覆盖当前可核验记录的汇总。

如果当前 Codex 环境没有发信连接或调度能力，相关步骤应显示“待完成”。电脑睡眠、断网、关机或桌面宿主退出，也会延迟检查。

## X 读取失败或历史不完整

服务可能限制匿名访问，公开页面结构也可能变化。读取失败不能解释成没有新公告；不要通过搜索缓存、旧 Feed、Nitter 或代理替代当前原帖。

Codex 路线读取 `agent scan` 的实际结果与 warnings，按[每轮执行说明](CODEX_MONITOR.md)判断是否有足够证据。原帖无法读取、内容截断或时间无法核实时，保留相应状态等待恢复。

独立 SMTP 路线运行 `check --dry-run`，结合 `status` 的 `health` 与 `error_type` 查看失败。当前实现也可能把模型分析失败写为 `source_ok: false`，不能仅凭这一字段认定是网络故障。终端可能只显示 `HTTPError` 等错误类型，具体 HTTP 状态诊断仍有限。

首次汇总会注明部分历史，不能据此声称完整七天统计；恢复联网也不能保证补回停机期间所有公告。

## 邮件结果不明确

`pending` 表示尚待发送；`unknown` 表示可能已经发出。预留邮件或生成预览都不能作为发送成功。

- Codex 路线：按[连接邮箱恢复流程](CODEX_MONITOR.md#4-用已连接的邮箱发送记录真实回执)，以主题、原帖 ID 和时间范围查询已发送记录。找到实际邮件后记录 provider 回执，禁止盲目重发。
- 独立 SMTP 路线：按[投递状态说明](ADVANCED_SETUP.md#投递状态)，先核对服务商日志、已发送或收件箱，再使用 `resolve`。

部分 SMTP 服务不会把提交的邮件存入“已发送”，查询不到也不能自动断言未发出。证据不足时保留 unknown。

## 独立 SMTP 或模型接口配置失败

这些配置只用于[高级手动路线](ADVANCED_SETUP.md)。`doctor` 通过仅表示配置格式正确；`test-email` 会真实发送一封演示邮件。

`ANALYSIS_MODE=llm` 需要使用者有权限使用的模型、HTTPS 接口与 API Key。请求异常、无效 JSON 或原文证据校验失败时，不应把模型猜测当作公告。Codex + 已连接邮箱路线不需要配置这里的 SMTP 或模型 API。

该路线已复现的无关回复重复提醒、空证据错误初始化问题见[已知问题](ADVANCED_SETUP.md#验证范围与已知问题)，本次文档整理未修复这些实现。

## 重启后重复首次汇总

请让 Codex 核对是否仍使用同一私有目录，以及是否还存在原来的定时任务。独立 SMTP 路线还应检查工作目录、`TIBO_DATA_DIR` 与 Docker 命名卷是否改变。

迁移时保留旧状态、明确目录和格式的兼容性；不要把 JSON 监测器、agent SQLite 与其他 SMTP 数据目录直接互换。先停止旧实例再进行明确规划的迁移。

## 时间看起来差了一小时

检查原文使用 PST、PDT 还是 PT。程序保留 PST/PDT 的字面偏移；与事件当日洛杉矶时区冲突时，显示未经确认的备选解释。未知日期或时区保留原文，`before` 是截止时间。

邮件中另列的“公告发布时间”不是实际重置时刻，预告截止时间过去也不等于已确认完成。

## 报告问题

提供使用路线、操作系统、Python 版本、失败步骤和脱敏的错误类别。请删除收件邮箱、授权码、API Key、Cookie、个人路径和邮件正文中的私人信息，不要上传 `.env` 或私有数据库。
